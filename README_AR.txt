الإصدار الرابع — قاعدة البيانات التاريخية والفهرسة والمقارنة الأسبوعية

ما أضيف:
1) قاعدة SQLite دائمة تحفظ الصفحات القانونية النشطة.
2) جدول document_snapshots لحفظ نسخة مؤرخة من كل صفحة في كل جولة.
3) جدول change_events لرصد الصفحات الجديدة والمتغيرة، والصفحات التي لم تظهر في جولة مكتملة بوصفها «محتمل حذفها» لا حذفاً مؤكداً.
4) محرك FTS5 للبحث النصي، مع إعادة بناء الفهرس عند تهيئة قاعدة البيانات.
5) زاحف يحترم robots.txt، ويقيد نفسه بمسارات القوانين والسوابق والعقود، ويستخدم مهلة بين الطلبات.
6) خدمة مستقلة للمتابعة كل يوم اثنين الساعة 10:00 بتوقيت آسيا/عدن.
7) واجهات API لحالة الفهرسة والتغييرات وتشغيل المزامنة يدوياً.

التشغيل:
- انسخ .env.example إلى .env.
- ضع ADMIN_TOKEN سرياً قوياً.
- نفّذ: docker compose up -d --build
- الواجهة: http://localhost:8000
- فحص الصحة: http://localhost:8000/api/health
- حالة الفهرسة: http://localhost:8000/api/sync/status
- التغييرات: http://localhost:8000/api/sync/changes

تشغيل الفهرسة يدوياً:
POST /api/admin/sync مع ترويسة x-admin-token بقيمة ADMIN_TOKEN.
أو داخل الحاوية: python backend/sync_yemenilaw.py --section all --max-pages 700

آلية الدقة:
- لا يسجل الزاحف صفحة على أنها محذوفة إلا بعد اكتمال الجولة دون أخطاء؛ وحتى حينها يسجلها «محتمل حذفها» لتجنب الجزم الخاطئ.
- الجولة الجزئية لا تنتج استنتاجات حذف.
- المحتوى المنشور في الموقع لا يثبت وحده أن النص تشريع رسمي أو أنه ما زال نافذاً.
- يجب الرجوع إلى الجريدة الرسمية أو الجهة المختصة للتحقق من النصوص والتعديلات والنفاذ.
- لا يجري البرنامج أي تعديل على موقع Yemenilaw ولا ينسخ محتوى إلى مكان عام.

حدود التشغيل في بيئة إعداد الحزمة:
جرى اختبار قاعدة البيانات ومحرك المقارنة محلياً ببيانات اصطناعية. تعذر الاتصال بنطاق yemenilaw.com من بيئة إعداد الملفات بسبب فشل تحليل DNS، لذلك لم تُنزّل صفحات الموقع الحقيقية ولم تُنشأ قاعدة بيانات محتوى حقيقية بعد. أول تشغيل على خادم متصل بالإنترنت سيبدأ خط الأساس التاريخي. لا تعتبر الحزمة مفهرسة بالكامل قبل نجاح أول جولة على الخادم.
